# tenqsp-paper

Code and supplementary files for the paper introducing TenQSP (in preparation).

Every figure and table of the paper is regenerated by one command from this repository,
with the versions of TenQSP and tenqsp-fit the paper cites. The supplementary model files
(the `.tq` text of every case study) are here too.

## Layout

| Folder | Content |
|---|---|
| `models/` | the case-study models as `.tq` files (Supplement S8) |
| `figures/` | one script per figure; each writes its figure to `out/` |
| `tables/` | one script per table |
| `checks/` | reproductions of published results the case studies build on, and checks of the numerics |
| `data/` | published data the case studies fit (theophylline: R's `Theoph` data set) |
| `results/` | stored simulation results, so figures redraw in seconds |
| `out/` | generated figures and tables (not tracked) |

## Reproducing

```bash
python -m pip install -r requirements.txt
python figures/fig7_spheroid.py      # redraws Figure 7 from results/ (seconds)
```

To recompute the results, run the figure's run scripts first. Each has a `--quick` mode on a
coarser grid (every reported number within about 3 % of the paper's grid) for a fast check.

### Figure 1: from equations to estimates

| Command | What it does | Time |
|---|---|---|
| `python figures/fig1_concept.py` | the model file, its equations (`to_latex()`), `explain()`, a run with its ledger, exact derivatives, and the fit of Figure 5 E-F | under 1 min |

Panel F reads the fit stored by `figures/fig5_friberg.py`. Model: `models/friberg_maturation.tq`.
The figure is drawn at full page width (7 in), and the script stops if any text leaves its box.

### Table 1: comparison with other tools

`tables/table1_comparison.md`, written by hand from each tool's documentation, with a source
for every cell and the points to word carefully.

| Command | What it does | Time |
|---|---|---|
| `python tables/table1_render.py` | the same as a Word file on landscape pages, `out/table1_comparison.docx` (needs pandoc) | seconds |

### Figure 2: transit chains and the eclipse phase

| Command | What it does | Time |
|---|---|---|
| `python figures/fig2_runs.py` | the computations of panels A-F | under 1 min |
| `python figures/fig2_transit.py` | draws the figure from `results/` | seconds |
| `python checks/baccam2006_reproduction.py` | the published influenza model the figure builds on | seconds |

Models: `models/savic_transit.tq` (transit absorption, the drug in transit on an axis) and
`models/influenza_eclipse.tq` (the target-cell-limited influenza model of Baccam et al. 2006
with the eclipse phase on an axis; one cell is the published model).

### Figure 3 and Table 2: verification

| Command | What it does | Time |
|---|---|---|
| `python tables/table2_runs.py` | runs TenQSP's 12 tutorials (one process each) and stores the numbers their checks measure | about 5 min |
| `python tables/table2_verification.py` | writes Table 2 from `results/` (`out/table2.md`, `out/table2.csv`) | seconds |
| `python figures/fig3_verification.py` | draws the figure from `results/` | seconds |

The 12 reference models are TenQSP's tutorials; each checks itself against a published model,
a closed form or a conservation ledger. By default the run script takes them from the source
distribution of the installed TenQSP version on PyPI; `--tutorials DIR` uses a local folder
(for instance `docs/tutorials` of a TenQSP checkout). Tutorial 2 takes most of the time
(about 5 min on its own).

### Figure 4: the reference models

| Command | What it does | Time |
|---|---|---|
| `python figures/fig4_runs.py` | runs TenQSP's 12 tutorials and stores each model's description and the amounts along its axes over time | about 5 min (12 processes) |
| `python figures/fig4_gallery.py` | draws the figure from `results/` | seconds |

The schematics are drawn from the models' descriptions (their axes, compartments and the
couplings written in them), not by hand. The tutorials come from the source distribution of
the installed TenQSP version, as for Table 2.

### Figure 5: estimation

| Command | What it does | Time |
|---|---|---|
| `python figures/fig5_runs.py` | panels A-C: 20 simulated studies, each fitted with chains of 3 to 60 transit compartments | about 10 min on 16 processes |
| `python figures/fig5_theoph.py` | panel D: the theophylline data fitted with first-order absorption and chains of 1 to 20 | about 3 min (one process per fit) |
| `python figures/fig5_theoph.py --dispersion` | panel D: the same data fitted with transport with an estimated dispersion, on 20 and 40 cells | about 35 min |
| `python figures/fig5_friberg.py` | panels E-F: Friberg's myelosuppression model fitted to a simulated dose-ranging study | about 1 min |
| `python figures/fig5_estimation.py` | draws the figure from `results/` | seconds |
| `python checks/nonmem/friberg_nonmem.py` | the Friberg fit against NONMEM's on the same data, from the same starts (Table S3); `... data` writes the data file for `checks/nonmem/friberg.ctl`, whose NONMEM estimates are stored in `results/nonmem/friberg.ext` | seconds (NONMEM: needs a licence) |

The fits use tenqsp-fit (in `requirements.txt`). Models: `figures/transit_fit.py` (the
transit model with dispersion that simulates the studies, and the chains that fit them) and
`models/friberg_maturation.tq` (the maturation chain written as an axis).

### Figure 6: whole-body PBPK as one field

| Command | What it does | Time |
|---|---|---|
| `python figures/fig6_runs.py` | the computations of panels B-E and the exact checks | about 1 min |
| `python figures/fig6_pbpk.py` | draws panels B-E from `results/` (panel A, the structure diagram, is drawn by hand) | seconds |

Model: `models/pbpk_wholebody.tq` (9 organs x 3 spaces, arterial and venous blood; the
model of TenQSP's tutorial 6). The run script also writes the model as 29 ODEs by hand and
checks the field against them.

### Figure 7: the tumour spheroid

| Command | What it does | Time (paper's grid / `--quick`) |
|---|---|---|
| `python figures/fig7_runs.py` | the simulations of panels A–E | about 3 min / 40 s on 8 cores |
| `python figures/fig7_gradients.py` | panel F: exact derivatives with respect to the time and amount of all 48 doses, from one run and one pass back per objective | about 30 min and 80 GB of memory / 6 min and 20 GB |
| `python figures/fig7_spheroid.py` | draws the figure from `results/` | seconds |
| `python checks/spheroid_gradients_vs_fd.py` | the exact derivatives against finite differences | about 8 min (quick grid) |
| `python checks/spheroid_tolerance.py` | the results do not depend on the solver's absolute tolerance | under 1 min (quick grid) |
| `python checks/lorz2015_reproduction.py` | the published results the case study builds on | about 2 min |

Times measured on a 64-core Linux workstation with nothing else running; a laptop is slower. The
full-grid derivatives need about 80 GB of memory; on a smaller machine use `--quick` (20 GB).

Models: `models/spheroid_lorz2015.tq` (the published model), `models/spheroid_pk.tq` (with
plasma pharmacokinetics, a saturable kill and the drug's penetration speed),
`models/spheroid_nodepth.tq` and `models/spheroid_notrait.tq` (the two simpler models it is
compared with).

### Table 3 and Figure S-perf: what a run costs

| Command | What it does | Time |
|---|---|---|
| `python tables/table3_runs.py` | one solve on each backend and one gradient, for 10 models from 3 to 16,242 states | about 1.5 h (the largest spheroid grid takes 1 h) |
| `python tables/table3_batches.py` | virtual populations on the CPU: one call per member, one batch on 1 core, one batch on 64 cores | about 2 h (the spheroid batches take most of it) |
| `python tables/table3_batches.py gpu` | the same batches on a GPU (an environment with CUDA JAX) | about 10 min |
| `python tables/table3_performance.py` | Table 3 (`out/table3.md`, `.csv`), the batch table (`out/table3_batches.md`) and Figure S-perf (`out/figS_perf.png`, `.pdf`) from `results/table3` | seconds |

The times are wall-clock seconds, so run on an otherwise idle machine; each result records the
machine's load when it started. The paper's numbers: TenQSP 0.8.3, a 64-core Linux workstation
with an RTX A6000, JAX 0.12.0.1 on the CPU and 0.11.2 on the GPU.
